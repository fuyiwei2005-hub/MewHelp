# 第五、六章 Workflow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking. 沿用用户当前会话内执行偏好，独立后端评审再使用reviewer。

**Goal:** 先手写Agent循环，再以LangGraph交付持久化Workflow、正式指代/意图与退款选单子流程。
**Architecture:** 父图固定分流，ReAct子图读工具，退款子流程interrupt选单后查订单和多查询检索；用户确认接口独占写操作。
**Tech Stack:** FastAPI/LangChain/LangGraph、官方AsyncPostgresSaver、MySQL/SQLAlchemy、既有Milvus/BGE服务、原生聊天页。
**Spec:** docs/superpowers/specs/2026-10-21-ch05-workflow-agent-design.md 与 2026-10-21-ch06-router-refund-design.md（第六章覆盖占位节点和售后路由）。

## Global Constraints

- 两章分别即时更新dev-notes/ch05.md、ch06.md，Prompt/数据标注评估；后端TDD，前端Vibe例外。
- 库/API使用前查Context7；固定兼容依赖，不换技术。PostgreSQL独立16432候选端口，MySQL/Milvus原卷保留。
- 指代仅当前会话；完整问题保留resolved原句，归一单独retrieval_query；intent/confidence仅两键，queries仅一键。
- 通用FAQ不选单不扩写，具体订单退款/售后先查单再扩写检索过闸。
- Agent不能写工单或退款；转人工仅前端，建工单/退款申请各自确认且幂等。
- 使用演示订单，本地退款申请不执行真实退款；新语料继续暂存不混入当前权威库。
- 当前feature分支内执行，不切main，不推送合并；已有未提交用户资料保留。

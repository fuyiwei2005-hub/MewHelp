## 2026-10-19 · 启动与前置核对

- 用户关键原话：“把 query_faq 的内部实现从关键词查表升级成向量语义检索,工具的入参出参契约保持不变”“先写 MySQL 记『待向量化』,再写 Milvus 拿 vector_id 回填”“故意中断建库任务再重跑”。
- 关键产出：沿用 Superpowers using-superpowers / brainstorming，属于新增知识库子系统的 Architectural 路径。核对发现仓库目前只有第一章对话/页面实现，第二章仅有待批准设计草案；app 中没有 query_faq、SQLAlchemy 四表或历史消息持久化，因此没有可沿用的实际工具契约与历史消息数据源。需用户确认先补齐第二章，或指定已有第二章代码位置；本阶段未编造已存在的接口。
- 用户拒绝或纠偏：暂无。固定 BGE-M3 + Milvus + MySQL，只做 dense 单路，不引入关键词召回、混合检索或重排。此前第二章为演示漏召回拟定的“禁止同义改写”规则，本章应随语义检索更新，但工具契约不能未经核对就重定义。
- 翻车与返工 / 环境：Docker 客户端存在，但 Linux 引擎仍未运行；MySQL / Milvus 均未验证启动。没有为了绕过环境替换向量库、嵌入模型或数据库。未安装依赖、下载模型、建表或修改运行代码。
- 文档核实：Context7 已解析并查询 FlagEmbedding BGE-M3 dense 编码、PyMilvus schema/upsert/search、LangChain 标题与递归切分接口。确认 dense 编码可显式关闭 sparse/ColBERT；Milvus 可使用自定义主键与 upsert 支持重复写，具体 SDK 版本实施时再锁定和核对；普通文本切分器不能自动保证大表格表头复制和完整句边界，需要专门规则与样例验证。
